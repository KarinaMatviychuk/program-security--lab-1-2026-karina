# Політика безпеки проєкту (Security Policy)
**Проєкт:** BookTrace — Трекер прочитаного  
**Версія:** 1.0.0  
**Автор:** Каріна Матвійчук (група ПЗ-23-1)  
**Статус:** Active  

---

## 1. Мета та область дії
Ця Політика безпеки визначає обов'язкові правила, принципи та обмеження, спрямовані на забезпечення безпеки розробки, збереження облікових даних користувачів та захисту персонального прогресу читання в застосунку BookTrace.
Політика поширюється на вихідний код у репозиторії, конфігураційні файли, CI/CD-пайплайни, середовище розробки та всіх розробників проєкту.

## 2. Ролі та відповідальність
* **Lead Developer / Security Officer (Каріна Матвійчук):** відповідає за затвердження політики, перегляд коду (Code Review), управління секретами та реагування на вразливості.
* **Contributors / Developers:** зобов'язані дотримуватися вимог цієї політики під час написання коду, створення комітів та підключення зовнішніх бібліотек.

## 3. Принципи безпеки
* **Principle of Least Privilege (Мінімальні привілеї):** доступ до даних книг та нотаток надається виключно їх власникові (`READER`) або авторизованому адміністраторову (`ADMIN`).
* **Defense in Depth (Багаторівневий захист):** захист даних реалізується на рівнях валідації вхідних даних, хешування паролів (bcrypt, 12 rounds), двофакторної автентифікації (TOTP МФА) та контролю сесій.
* **Secure by Default:** за замовчуванням усі ендпоінти API вимагають обов'язкової автентифікації (`requireAuth`).
* **Zero Trust Secrets:** заборонено зберігати сесійні ключі, паролі, TOTP-секрети та токени у відкритому вигляді у вихідному коді.

## 4. Безпека автентифікації та паролів
* **Зберігання паролів:** заборонено зберігати паролі у відкритому або зашифрованому з можливістю відновлення вигляді. Використовується засолене хешування `bcrypt` із складності в 12 раундів.
* **Захист від брутфорсу (Lockout Policy):** при отриманні 5 послідовних невдалих спроб входу акаунт тимчасово блокується.
* **Багатофакторна автентифікація (МФА):** підтримується генерація та перевірка 6-значних одноразових паролів на основі часу (TOTP, RFC 6238).

## 5. Безпечне середовище розробки та Git
* **Автентифікація:** доступ до віддаленого репозиторію GitHub здійснюється за протоколом SSH з використанням асиметричних ключів.
* **Захист гілок:** прямий push у гілку `main` заборонений. Зміни вносяться черезPull Requests.
* **Управління секретами:** усі секретні ключі сесій зберігаються в змінних оточення (`.env`), доданих до `.gitignore`.

## 6. Управління вразливостями
* **Аналіз залежностей:** підключені Node.js пакети перевіряються за допомогою `npm audit`.
* **Реагування:** критичні вразливості в залежностях усуваються протягом 24 годин шляхом оновлення версій пакетів.
