# Стратегія контролю цілісності та модель ліцензування "BookTrace"
**Проєкт:** BookTrace (Reading Tracker)  
**Варіант:** 8 (Матвійчук Каріна, група ПЗ-23-1)  

## 1. Модель розповсюдження та захисту від несанкціонованого копіювання
* **Модель розповсюдження:** **SaaS + Freemium**.
  * **FREE-рівень:** базовий функціонал трекера з обмеженням до 2 активних книг на обліковий запис.
  * **PRO-рівень:** зняття обмеження на кількість книг та доступ до функцій резервного копіювання з підписом.
* **Механізм захисту ліцензії:** асиметричний цифровий підпис **Ed25519** (EdDSA).
  * Сервер ліцензування підписує JSON-пейлоад ліцензії (`email`, `plan: "PRO"`, `expiresAt`) **закритим ключем (Private Key)**.
  * Модуль перевірки володіє лише **відкритим ключем (Public Key)**. Навіть при реверс-інженерії клієнтського коду зловмисник не зможе згенерувати валідну PRO-ліцензію або підробити термін її дії.
  * Для ускладнення статичного та динамічного аналізу модуль перевірки ліцензії захищено обфускацією (Control Flow Flattening + обфускація ідентифікаторів).

## 2. Стратегія контролю цілісності даних
* **Дані, на які впливає користувач:** прогрес читання (`readPages`), загальна кількість сторінок (`totalPages`), текст нотаток, ліцензійний токен.
* **Ризики модифікації:**
  1. Передача від'ємних значень або перевищення `readPages > totalPages` (спотворення статистики).
  2. Підміна параметрів PRO-ліцензії у запиті активації (несанкціоноване отримання платних функцій).
  3. Модифікація збережених нотаток або експортованого прогресу.
* **Механізми контролю цілісності:**
  * **Ed25519 Digital Signature:** криптографічна перевірка автентичності та цілісності ліцензійного ключа перед активацією PRO-статусу.
  * **HMAC-SHA256 (MAC):** формування коду автентичності для експорту/звіту про прогрес читання користувача.
  * **AES-256-GCM Auth Tag:** контроль цілісності зашифрованих нотаток (реалізовано в ЛР №4).
  * **Серверна валідація інваріантів:** жорстка перевірка `0 <= readPages <= totalPages` на стороні сервера.
